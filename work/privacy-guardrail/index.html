Adding patient context to privacy scans

tl;dr: A content scan can find a name or a phone number, but it cannot tell whether it belongs to a patient or a doctor. I built a prototype guardrail that adds that context, gives every file one verdict with a logged reason and holds anything uncertain for review before it reaches the analytics platform. It was built on one data source as a pattern to extend to others.

The problem

Patient data needed a check before it entered an analytics platform. A content scan can find a name, address or phone number, but it cannot tell whether those fields describe a patient or a healthcare provider. On its own, it misses patient data that has no obvious identifiers and flags provider data that is not sensitive.

What I built

A mapper that turns nested scan output into one clean table, with automated tests behind it.

A rules-based context engine that uses the documented data classification and the interface agreement to work out who each file describes.

One verdict per file: quarantine, safe, review or clear, each logged with its reason. Anything unclassified defaults to review, and row-level evidence can escalate a verdict but never downgrade it.

As an independent check, I wrote a specification for one object and had an AI coding agent build a separate version from it. It reached the same verdicts as the hand-built engine.

Why it matters

It stops patient data from reaching the analytics platform just because a scan did not recognize it, and it stops provider data from being blocked just because it contains a name.

Every decision comes with a reason, so a reviewer can see why a file was held and an auditor can trace it later. Uncertain files wait for a person instead of being guessed at.

The judgment call

I also tested whether a machine learning model could make the call. On the small set of labeled files, it was not reliable enough to decide on its own, so I kept its score advisory and let the rules decide. A false clear costs far more than an extra review.

Next steps

This was a prototype on one data source, built so the same pattern could extend to other sources. Next were broader row-level coverage, a live reference lookup and an audit dashboard.
